# Deterministic Win32 staging

Run Build-ESAFPackage.ps1 in Windows PowerShell 5.1 with a non-synced OutputRoot such as C:\ESAFBuild. It cleans only the recognized ESAF-Package child, stages an explicit runtime allow-list, validates syntax/JSON and generates package-manifest.json with versions, UTC build time, entrypoints and SHA-256 hashes. PackageSupport.ps1 validates inventory, hashes and metadata; it never executes manifest data. Hashes detect corruption, not replacement of both manifest and bootstrap code. Sign reviewed source before staging.

Engine 0.3.0 staging retains all earlier hardening and includes the Milestone 5 support exporter. Bootstrap includes installer, detection, uninstall PS1/CMD, integrity and lock helpers. Payload includes only runtime src, fourteen controls, Corporate-W11 1.1.0 baseline and three runtime console/verification tools. The package build reads the engine version from `src/ESAF.psd1`; package validation accepts only the current release metadata. Tests, workflows, build/security-scan scripts, .git, evidence and third-party binaries are excluded. Content Prep is never downloaded; supply an approved -ContentPrepToolPath explicitly or run it manually outside staging. See [the pilot guide](../docs/INTUNE_PILOT_GUIDE.md).

The current pilot uses unsigned scripts with a process-only `-ExecutionPolicy Bypass` launcher; this does not persistently alter endpoint execution policy. Production should prefer signed release scripts and normal organizational script-control policy. Rebuild staging and .intunewin after the uninstall launcher correction so its hash is regenerated; never edit hashed staged files in place. Update the existing one-device app install command from the pilot guide before retrying.
